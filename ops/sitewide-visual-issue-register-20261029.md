# Stonebridge — whole-site mobile/desktop visual composition register
**Review date:** October 29, 2026
**Starting production branch:** `main`, commit `0939e8439d63b5b42aace1ea90320c9c8baf73d4`
**Intent:** Preserve the current Stonebridge design; identify only evidenced defects and document KEEP decisions. This report is not a redesign approval.
**Release status:** Audit-only draft. No production changes.

## How visual decisions were made
The 26 root HTML entries were rendered on a local static-server copy at **320, 360, 390, 430, 768, 1024, 1280, 1440, 1920 CSS px** in headless Chromium 156 at 1× DPR, with full-page screenshots at 390px and 1440px for each entry. The actual full-page captures were examined in grouped mobile and desktop contact sheets; the New Clients, Professionals and The Lobby desktop compositions were separately inspected in higher-resolution cropped images. Section bounding boxes, heading widths, scroll heights and paragraph font sizes were checked against rendered DOM measurements. Some files redirect to another page, so their hidden/dormant HTML was **not** treated as an independently visible page.

Visual judgment deliberately distinguishes **KEEP** (no verified problem in the examined composition, preserve the existing design) from **CHANGE** (an observable problem with a specific correction) and **REVIEW** (potential editorial/owner decision; no unauthorised change). KEEP is not a universal WCAG, SEO or visual-quality certification.

The full-site screenshot proof is attached to the previously generated <a href="https://github.com/s1bryant019-cell/stonebridge-website/actions/runs/40806728859">26-page visual capture run</a>, artifact `stonebridge-mobile-desktop-visual-proof`; separate before/after galleries are attached to the change PRs below. The production code itself has not been altered.

## 3. Owner-only editorial / clinical review queue
No copy is changed in any draft PR.
- **New Clients:** hero H1, long H2 and both cards repeatedly express “request appointment / ready to begin.” Proposed, *not approved*: replace only introductory H2 with “Choose your next step”; distinguish appointment versus optional consultation and preserve pending confirmation and emergency language.
- **About and clinician profiles:** review whether practice philosophy and repeated availability/fit language adds meaning at the decision point; retain clinical credentials, specializations, supervision and professional statements verbatim.
- **Home:** retain existing appointment-first decision until the practice explicitly authorizes a consultation-first CTA reversal. Brand positioning text alone is not permission to change it.
- **Privacy & Fees:** any reduction of legal/privacy disclosures or insurer/fee details needs owner/legal/clinical approval. Do not convert a density concern into a missing factual qualification.
- **Careers:** approve a dedicated employment contact or application path before changing the currently mismatched future-interest links.

## 5. Scorecard — twelve independent categories, both devices
The requested rubric has twelve categories: **Redundancy & Clarity, Comprehension, Complexity Control, Hierarchy, Grouping, Consistency, Craftsmanship, Readability, Distinctiveness, Function, Accessibility, Premium Feel**. A companion `ops/sitewide-visual-scorecard-20261029.csv` lists all 26 entries separately at mobile and desktop and each of these twelve category cells.

**Rule used:** do not invent 9.0/9.5 scores from screenshots alone. Each category that cannot be reliably proven to the user's threshold is marked `N/V — NOT VERIFIED`. Where a specific evidenced failure exists, the row verdict says `NOT APPROVED`; where automated evidence is clean but critical manual/cross-browser work remains, it says `INCOMPLETE VERIFICATION`. No average is used to obscure a failure.

**No page is certified at the 9.0/9.5 target on both devices yet.** In particular, no category can honestly be scored above the target without an owner-approved visual/design rubric calibrated against actual full-size before/after comparisons, touch/zoom/keyboard, and independent page content review.
